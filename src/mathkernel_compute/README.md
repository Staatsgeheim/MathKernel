# Optional compute orchestration

This optional pilot provides the common planning, authorization, journal, worker
and verification boundary, with Linux local CPU, existing Linux SSH hosts and a
native single-job Slurm adapter. Experimental Modal Sandbox and existing Runpod
queue adapters add scoped paid approval, native USD reservations, durable provider
artifacts and independent batches. Read [remote setup](REMOTE.md) for SSH/Slurm and
[managed setup and qualification limits](MANAGED.md) before configuring paid targets.
Live cloud/GPU qualification, Apptainer and VM provisioning remain outstanding.

Install from this branch with `python -m pip install '.[compute]'`. The extra adds
RFC 8785 canonicalization and SciPy. Core import does not import this package,
contact providers, load credentials or launch workers. Legacy `MathKernel.job_*`
and the Studio workflow service remain independent and retain their APIs.

## Supported operations

| Operation | Input and implementation | Locally admitted claim |
| --- | --- | --- |
| `cuboid_sweep` version 1 | Integer-text bound 2–2000; existing Python sweep or explicitly selected CUDA engine on a pinned managed GPU profile | Exact listed Pythagorean identities; optional full bounded coverage checked independently through Euclid's primitive-triple parameterization and integer scaling |
| `signal_convolve` version 1 | Two real decimal-text vectors, 1–256 samples each; existing SciPy numeric convolution | Numerical full zero-padded convolution of the binary64 inputs, checked against a 100-digit Decimal reference with a stated infinity-norm tolerance |

Operation descriptors and parameter-schema digests are generated by
`mathkernel_compute.registry.descriptors()`. This registry is distinct from the
kernel's mathematical capability catalog. It is not a universal RPC interface.

These bundles are self-contained. Arbitrary object references, inherited contexts,
custom code, worker-selected paths/URLs, exact-to-numeric fallback, complex arrays
and generic NPY/CSR artifacts are not supported. A field reserved in the design is
not accepted until its adapter exists. Numeric sample ancestry stays numeric;
remote labels cannot establish formal or interval-certified evidence.

## CLI journey

Save `request.json`:

```json
{"operation":"cuboid_sweep","parameters":{"bound":"50"}}
```

Then run each action explicitly:

```sh
mathkernel-compute --state-dir ./compute-state targets
mathkernel-compute --state-dir ./compute-state plan request.json
mathkernel-compute --state-dir ./compute-state approve-local PLAN_ID
mathkernel-compute --state-dir ./compute-state submit PLAN_ID --grant GRANT_ID --request-id my-request-1
mathkernel-compute --state-dir ./compute-state reconcile JOB_ID
mathkernel-compute --state-dir ./compute-state verify JOB_ID
mathkernel-compute --state-dir ./compute-state result JOB_ID
```

Use the actual references returned by the commands. `approve-local` is a trusted
host action: it prints the plan and requires its digest to be typed at a terminal.
It is not an agent-facing MCP operation. Python host applications can use the
private `_authorize_local` integration point; possession of arbitrary request
fields does not issue a grant. Remote execution has a separate exact-scope
`approve-remote` action; local grants cannot export inputs. Paid targets require a
separate `approve-managed` grant acknowledging export, persistent storage and the
described exposure; see [MANAGED.md](MANAGED.md). Neither local nor SSH grants can
authorize a paid invocation.

`status` and `result` read retained facts. `reconcile` explicitly observes the
supervisor and collects output. `verify` performs a separate local check. Until
that check passes, `result` returns a receipt without mathematical trust. Python
`accepted_result()` refuses candidates. `candidate` returns a clearly unverified
DTO. `cancel` records an idempotent cancellation request; reconcile again to observe
stop and resource release. `replay` exports inert data, never an executable script
or grant. `list` returns a bounded first page; the Python API supports paging.

The numerical request is explicit:

```json
{"operation":"signal_convolve","parameters":{"left":["1.5","2.5"],"right":["2","-1"]},"required_claim":"numeric_convolution"}
```

## Ownership and durability

One coordinator locks a private state directory. A separate SQLite schema (version
1) uses WAL/FULL commits, integrity hashes, request/attempt uniqueness, intent
records, revisions, grants and reservations. No legacy KernelStore migration is
performed. Unknown journal versions are rejected. The directory is local storage,
not a distributed database or multi-tenant service.

Python clients reconcile already-authorized intents on open by default. Use
`reconcile_on_open=False` for discovery or inspection; CLI commands use this mode
and invoke recovery explicitly.

Plan bytes pin the input bundle, exact operation contract, runtime code identity,
Python/dependency versions and operator policy. Changes or expiry invalidate new
side effects. A plan performs no input staging or worker launch. Submission commits
job/attempt/resource/reservation/outbox intent before launch. Concurrent retries
with the same request identity return the original attempt. Ambiguous submission
retains exposure and is observed without a replacement dispatch.

The detached local supervisor survives ordinary controller exit, retains a bounded
candidate in its attempt spool, enforces the worker deadline, and cleans its owned
process group. Linux subreaper ownership lets it reap descendants. PID/start-time
identity protects observation from PID reuse. The scientific worker receives a
small allowlisted environment, no controller credentials, and a length-prefixed
JSON frame. The worker never receives a pickled kernel or callable.

Cancellation is an intent, not proof of cleanup. A dead supervisor is reported
`LOST` / `CLEANUP_UNKNOWN`; the controller does not guess that a PID is safe to kill.
There is no independent external watchdog for supervisor/host failure. A launch
whose outcome cannot be established can remain `SUBMISSION_UNKNOWN` pending
operator investigation. This is deliberately not an exactly-once guarantee.

## Limits and qualification

Default limits are one active job, one attempt, a 60-second execution deadline,
a separate 60-second verifier deadline, a 1-MiB frame/output limit, and 1,000 retained
jobs (up to four plans/grants per job capacity). All limits are finite and strict;
no boolean masquerades as an integer. A wait timeout does not cancel execution.
The JSON profile forbids floating metadata numbers and uses decimal strings;
[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785) supplies canonical encoding.

Worker completion, local verification, artifact availability, resource cleanup and
cost are independent observations. Local provider allocation cost is zero;
electricity and hardware usage are unmeasured. This pilot has no paid-account
budget grant or provider-enforced spend cap. Cleanup uncertainty retains concurrency
reservation. No worker network isolation, hard RAM quota, Windows Job Object,
macOS process supervision or external-host/cluster qualification is advertised.
SSH/Slurm profiles are native pilots with explicit operational limitations.

Supervisor/controller source is trusted installed code. The process boundary is
not an arbitrary-code sandbox. Candidate data is bounded, quarantined, bound to the
attempt/input/execution and locally checked before **new local** evidence reaches
`MathResult`. Worker `trust`, `verified`, image and support-path labels remain
untrusted metadata. A verifier timeout is `INCONCLUSIVE`, not a false mathematical
claim. Conflicting candidate bytes cannot replace a retained attempt output.

This pilot has no new MCP tools or Studio compute adapter yet. Those integrations
can consume the common service once their host-owned lifecycle is wired and tested.
The existing Studio execution tier remains available separately.
